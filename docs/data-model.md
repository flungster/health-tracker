# Data model

The schema is owned entirely by dbmate migrations in `db/migrations/`. The API
never alters the schema. This document describes the current model (as of the
`20260823000002_activities` migration) and the conventions it follows.

## Conventions

- **Audit columns** — every table carries `created_at`, `updated_at`, and
  `deleted_at` (`timestamptz`). The two exceptions are the bulk, immutable
  sample tables (`activity_trackpoints`, `strength_exercise_sets`), documented
  below.
- **Soft delete** — deletion sets `deleted_at`; a row is active while
  `deleted_at IS NULL`. All reads filter on it.
- **`updated_at` is maintained by a trigger** (`set_updated_at`) so every write
  path stays correct without each code path remembering to set it.
- **Identifiers** — public-facing rows (`users`, `activities`) use `uuid`
  (v4, generated by the API) so they are safe in URLs. Internal bulk rows use
  `bigint` identity columns.
- **Ownership** — every user-owned row has a `user_id` (or `activity_id` that
  cascades to one), and every read is scoped to the caller. Other users' rows
  are indistinguishable from missing rows (404).
- **Timestamps** — stored as UTC `timestamptz`.
- **Sport types** — stored as `text` with a `CHECK` constraint listing the
  allowed values, rather than a Postgres `ENUM` (easier to evolve, standard
  SQL).
- **Standard SQL** — the schema avoids Postgres-specific types so it stays
  portable and the migrations stay simple.

## Relationship overview

```
users 1───┬───1 user_profiles
          │
          └───* activities 1───┬───* activity_trackpoints
                               ├───1 activity_hr_zones
                               ├───* activity_splits
                               ├───1 running_activity
                               ├───1 cycling_activity
                               ├───1 rowing_activity
                               └───┬───1 strength_activity
                                   └───* strength_exercise_sets
```

`users` cascades to `activities`; `activities` cascades to all of its
sub-resources. Deleting a user removes their activities and everything under
them (soft delete at each level).

## Tables

### `users`

Application accounts.

| Column | Type | Notes |
|---|---|---|
| `id` | `uuid` PK | Public identifier (UUIDv4). |
| `first_name` | `text` | |
| `last_name` | `text` | |
| `email` | `text`, unique | Normalized (trim + lowercase) before storage. |
| `password_hash` | `text` | argon2id hash; plaintext never stored. |
| `created_at` / `updated_at` / `deleted_at` | `timestamptz` | Audit columns. |

### `user_profiles`

Per-user health settings, 1:1 with `users` (PK is `user_id`). Drives
heart-rate zone computation.

| Column | Type | Notes |
|---|---|---|
| `user_id` | `uuid` PK, FK → users | |
| `max_heart_rate` | `int` NULL | 1–300 bpm. Used to derive the five zones. |
| `resting_heart_rate` | `int` NULL | 1–300 bpm. |
| audit | | |

### `activities`

Imported sport activities — the core table. Holds every metric that applies to
most sports; sport-specific metrics live in the 1:1 `<sport>_activity` tables.

| Column | Type | Notes |
|---|---|---|
| `id` | `uuid` PK | Public identifier. |
| `user_id` | `uuid` FK → users | Owner; every query is scoped to this. |
| `sport_type` | `text` | `CHECK` against the canonical sport set. |
| `name` | `text` | From the file or user-chosen. |
| `description` | `text` NULL | |
| `started_at` / `ended_at` | `timestamptz` | UTC; `ended_at >= started_at`. |
| `duration_seconds` | `int` | `ended_at - started_at`; ≥ 0. |
| `moving_seconds` | `int` NULL | When the source provides it. |
| `distance_m` | `double` NULL | Meters; NULL for non-GPS sports. |
| `calories_kcal` | `double` NULL | From the file when available. |
| `elevation_gain_m` | `double` NULL | Cumulative positive gain. |
| `heart_rate_min/avg/max_bpm` | `int` NULL | Each `> 0` when set. |
| `cadence_avg_rpm` | `int` NULL | `> 0` when set. |
| `source_format` | `text` | `gpx` / `tcx` / `fit` / `apple_health`. |
| `original_filename` | `text` NULL | As uploaded (for display). |
| `file_path` | `text` NULL | Storage path of the original file in the uploads volume. |
| audit | | |

Indexes: `(user_id, started_at DESC)` for the feed, `(user_id, sport_type)`.

### `activity_trackpoints`

One row per recorded sample (GPS position + physiology). Bulk, immutable —
**no audit columns by design**.

| Column | Type | Notes |
|---|---|---|
| `id` | `bigint` PK (identity) | Internal. |
| `activity_id` | `uuid` FK → activities | Cascades. |
| `seq` | `int` | 0-based sample order; unique with `activity_id`. |
| `recorded_at` | `timestamptz` NULL | |
| `lat` / `lon` | `double` NULL | WGS84; `NULL` for non-GPS samples. Ranged `[-90,90]` / `[-180,180]`. |
| `altitude_m` | `double` NULL | |
| `heart_rate_bpm` | `int` NULL | `> 0` when set. |
| `cadence_rpm` | `int` NULL | `> 0` when set. |
| `speed_mps` | `double` NULL | ≥ 0. |
| `power_w` | `int` NULL | Cycling/rowing; `> 0` when set. |

The `0` values a device reports as "no data" for cadence/power/HR are
normalized to `NULL` on import (the columns are constrained `> 0`).

### `activity_splits`

Precomputed per-distance splits, one row per split, for both kilometres and
miles. Computed from trackpoints at import time.

| Column | Type | Notes |
|---|---|---|
| `id` | `bigint` PK (identity) | |
| `activity_id` | `uuid` FK → activities | |
| `split_type` | `text` | `km` or `mi`. |
| `split_index` | `int` | 1-based within its unit; unique with `(activity_id, split_type)`. |
| `duration_seconds` | `int` | Time to cover this split. |
| `pace_seconds` | `double` | Seconds per km (or per mile). |
| `heart_rate_avg_bpm` | `int` NULL | Per-split average, when available. |
| `cadence_avg_rpm` | `int` NULL | Per-split average, when available. |
| audit | | |

### `activity_hr_zones`

Seconds spent in each of the five heart-rate zones, 1:1 with `activities`
(PK is `activity_id`). Computed at import from the trackpoint heart rates and
the user's max HR (or the activity's own max HR when the profile is unset).

| Column | Type | Zone (percent of max HR) |
|---|---|---|
| `zone_1_seconds` | `int` | < 56% (warmup) |
| `zone_2_seconds` | `int` | 56–63% (easy) |
| `zone_3_seconds` | `int` | 64–71% (tempo) |
| `zone_4_seconds` | `int` | 72–80% (threshold) |
| `zone_5_seconds` | `int` | > 80% (VO2 max) |
| audit | | |

### Sport-specific tables (1:1 with `activities`)

Each is keyed by `activity_id` (PK, FK → activities) and only has a row when
the activity's `sport_type` matches.

- **`running_activity`** — `avg_pace_s_per_km`, `min_pace_s_per_km`,
  `max_pace_s_per_km`.
- **`cycling_activity`** — `power_avg_w`, `power_max_w`.
- **`rowing_activity`** — `stroke_rate_avg_spm`, `stroke_rate_min_spm`,
  `stroke_rate_max_spm`, `split_500m_seconds`.
- **`strength_activity`** — `total_sets`, `total_exercises`,
  `total_weight_kg` (total lifted volume).

### `strength_exercise_sets`

Per-set detail for strength activities. Bulk, immutable — **no audit columns
by design**. (Populated by manual strength entry, not by file import, at the
time of writing.)

| Column | Type | Notes |
|---|---|---|
| `id` | `bigint` PK (identity) | |
| `activity_id` | `uuid` FK → activities | |
| `exercise_name` | `text` | e.g. "Squat". |
| `set_index` | `int` | 1-based within the exercise. |
| `reps` | `int` NULL | NULL for time-based sets. |
| `weight_kg` | `double` NULL | NULL for bodyweight sets. |
| `rest_seconds` | `int` NULL | When the source provides it. |

## Migrations

| File | Adds |
|---|---|
| `20260823000001_initial.sql` | `set_updated_at()`, `users`, `user_profiles`. |
| `20260823000002_activities.sql` | `activities`, `activity_trackpoints`, `activity_splits`, `activity_hr_zones`, the four `<sport>_activity` tables, `strength_exercise_sets`. |

Each migration file contains both `-- migrate:up` and `-- migrate:down`
sections; `down` actually reverses the change.
